## Назначение

Документ объединяет то, что `xlvba` **не** поддерживает, где он валидирован и какие модели поведения
предполагаются, а не доказаны. Он дополняет [Возможности Excel](06-excel-capabilities.md) (которая
составляет карту поверхности возможностей) и [Устранение неполадок](10-troubleshooting.md) (которая
объясняет, как диагностировать сбои).

В документе используются две метки:

- **Проверено (Verified)** — поведение определено кодом или наблюдалось на валидированной сборке;
  утверждение является фактом об этой ревизии.
- **Предполагается / не проверено (Suspected / not verified)** — путь разрешён или подразумевается,
  но поведение не валидировано на целевой сборке. Считайте это недоказанным.

## Совместимость

| Область | Поддерживается / валидировано | Примечания |
|---------|-------------------------------|------------|
| Операционная система | Windows 10/11 x64; валидировано на Windows 10 Enterprise LTSC 2019 (сборка 17763) | Только Windows. COM (`pywin32`) и VBIDE доступны только на настольной Windows. |
| Excel | Настольный Microsoft Excel с COM/VBE; валидировано на 16.0.14332 x64 | Универсальная (Microsoft Store / UWP) версия обычно не подходит. Office должен быть активирован и запущен вручную хотя бы один раз. |
| Python | `>=3.11,<3.15` (нижний предел проекта 3.11); валидировано на 3.14 x64 | `.python-version` фиксирует 3.14. `pywin32` 312 поставляет wheel `cp314`. |
| Менеджер пакетов | [uv](https://docs.astral.sh/uv/) | `uv sync --locked` создаёт `.venv/` и консольный скрипт `excel-vba-mcp`. |
| Транспорт | MCP поверх STDIO | Протокол на `stdout`; логи и трассировки на `stderr`. Нет сетевого слушателя. |
| MCP-клиенты | Kilo, Claude Desktop / общие MCP-клиенты | Клиент запускает сервер как локальный дочерний процесс; инструменты показываются с префиксом клиента (например, `xlvba_excel_open`). |
| Форматы книг | `.xlsm` валидирован; `.xlsb`, `.xlsa`, `.xlam`, `.xltm`, `.xltx`, `.xlsx`, `.xls` разрешены path policy, но **не** проверены | Только `.xlsm` — валидированная область. Поведение с другими расширениями не проверено. |
| Доступ к проекту VBA | Доверие VBOM включается вручную на каждой машине | Без него инструменты VBA возвращают `ACCESS_VBOM_DISABLED`. Заблокированные проекты возвращают `VBA_PROJECT_LOCKED`. |
| Настольная интеграция | Скрытый, неактивируемый экземпляр Excel через `DispatchEx` | Без GUI, без `.Activate`/`.Select`, без `SendKeys`. |

### Подробности о форматах книг

Path policy принимает следующие расширения. Валидирован только `.xlsm`.

| Расширение | Роль в Excel | Статус валидации |
|------------|--------------|-------------------|
| `.xlsm` | Книга с поддержкой макросов | Валидирован |
| `.xlsb` | Бинарная книга (с поддержкой макросов) | Разрешён, не проверен |
| `.xlsa` | Надстройка Excel | Разрешён, не проверен |
| `.xlam` | Надстройка с поддержкой макросов | Разрешён, не проверен |
| `.xltm` | Шаблон с поддержкой макросов | Разрешён, не проверен |
| `.xltx` | Шаблон | Разрешён, не проверен |
| `.xlsx` | Стандартная книга | Разрешён, не проверен |
| `.xls` | Устаревшая книга | Разрешён, не проверен |

Надстройки и шаблоны могут не открываться как обычные книги; считайте любое не-`.xlsm` поведение
недоказанным, пока не протестируете на копии.

## Функциональные ограничения

| Ограничение | Подробности | Проверено/Предполагается |
|-------------|-------------|--------------------------|
| Нет создания книги | Инструмента новой книги нет. `excel_open` открывает только существующий файл. | Проверено |
| Нет создания или удаления PivotTable/PivotCache | Инспектировать, обновлять и перенастраивать можно только существующие PivotTables и кэши. | Проверено |
| Нет диаграмм, сводных диаграмм или слайсеров | Ни один инструмент не перечисляет, не создаёт, не форматирует и не удаляет их. Диаграммный лист появляется только как запись `chart` в `sheets_list`. | Проверено |
| Нет размеров строк/колонок, закрепления областей или параметров страницы | Ни один инструмент не предоставляет высоту строки, ширину колонки, закрепление областей, настройки печати/страницы или масштаб. `range_get_format` охватывает только ячейки. | Проверено |
| Нет изменения защиты листа | `sheets_list` / `sheet_get` сообщают флаг `protected` только для чтения. Инструмента защиты/снятия защиты нет; мутация защищённой цели возвращает `PROTECTED_TARGET`. | Проверено |
| Нет форсированного пересчёта | `Application.Calculate` (и `CalculateFull` / `CalculateRow` / свойства вычисления) не предоставляется. `range_read_values` возвращает то, что Excel удерживает в данный момент; ничто не форсирует пересчёт. | Проверено |
| Нет буфера обмена / межкнижного копирования | `range_copy` работает в пределах одной книги и никогда не использует буфер обмена. Копирование листа — только внутри книги. | Проверено |
| Нет внешних ссылок, подключений или запросов | Ни один инструмент не перечисляет, не обновляет и не редактирует внешние ссылки, подключения к данным или определения Power Query. | Проверено |
| Нет импорта/экспорта, печати, PDF или электронной почты | Нет импорта/экспорта CSV, экспорта в PDF, печати, электронной почты или конвертации файлов. `vba_export_project` экспортирует только исходники VBA. | Проверено |
| Нет событий | Ни один инструмент не регистрирует, не перечисляет и не редактирует события книги/листа. Процедуры событий ActiveX только предполагаются для чтения. | Проверено |
| Нет инструмента approval-гранта | Гранты approval и записи allowlist нельзя выдать или отредактировать через MCP. Классификация `background_safe` **доступна** через `macro_classify_background`. | Проверено |
| Компиляция всегда `indeterminate` | На валидированной сборке `vba_compile` возвращает `status="indeterminate"`, `reason="NON_ACTIVATING_COMPILE_UNAVAILABLE"`, `diagnostics.is_compile=false`. Он никогда не возвращает `compiled` или `compile_error`. | Проверено на 16.0.14332; предполагается на других сборках |
| Макросы требуют классификации `background_safe` | `macro_run` запускает только процедуру, классифицированную `background_safe` для текущего хэша книги и ревизии исходников VBA. Неклассифицированная процедура возвращает `BACKGROUND_SAFETY_NOT_VERIFIED`; интерактивная — `INTERACTIVE_UI_NOT_SUPPORTED`. | Проверено |
| `EXCEL_VBA_MCP_LOG_LEVEL` разбирается, но не применяется | Логирование настраивается во время импорта с фиксированным уровнем `INFO` на `stderr`; переменная не имеет эффекта в этой ревизии. | Проверено |
| Сопоставление событий ActiveX предполагается | Вероятная процедура события выводится из именования `<sheet_code_name>_<control>_<Event>`. Она никогда не проверяется кликом и может отсутствовать или быть неверной. | Предполагается / не проверено |
| Восстановление сессии не выставлено как MCP-инструмент | `SessionService.recover_session` существует внутри, но ни один MCP-инструмент его не запускает. Единственное исключение — зависание/таймаут `macro_run`, которое завершает принадлежащий PID и пересоздаёт экземпляр в процессе (F2b), сообщая `session_recovery` и отбрасывая открытые книги; `excel_health` показывает `needs_recovery` для всех прочих случаев, где решение — закрыть/открыть или перезапуск сервера. | Проверено |
| `pywinauto` не является зависимостью | `pywinauto` удалён из `pyproject.toml` и `uv.lock`; VBE-диагностика UI компиляции использует `comtypes` `IUIAutomation` (только чтение). Не ожидайте API `pywinauto`. | Проверено |
| Отсутствуют ручные фикстуры | `LockedProject.xlsm` и `TableNamesProject.xlsm` не закоммичены; связанные тесты пропускаются с явными причинами. | Проверено |
| Не-`.xlsm` форматы разрешены, но не валидированы | Allowlist путей принимает перечисленные выше расширения, но на целевой сборке валидирован только `.xlsm`. | Предполагается / не проверено |
| У `macro_run` нет предусловия снапшота | В отличие от контент-мутирующих инструментов, `macro_run` не требует предварительного `snapshot_create` (задокументированное отклонение от спеки). | Проверено |
| Preflight R13 эвристичен | Токен-скан — это вето, а не статическое доказательство; динамическая косвенность `CallByName`/`ExecuteGlobal`/`Eval` и транзитивный UI покрыты не полностью. | Проверено |
| Защита от диалогов макроса — defense-in-depth, а не блокиратор диалогов | F2a выставляет `Application.Interactive=False` / `DisplayAlerts=False` вокруг единственной диспетчеризации `Application.Run` и восстанавливает их в `finally`; подавляются только встроенные предупреждения Excel, но не `MsgBox`/`UserForm.Show`/`FileDialog`/UI надстроек/Win32-диалоги. | Проверено |
| `excel_health` может отставать от мёртвого воркера, когда слой Win32 недоступен | Liveness-проба owned-pid требует слоя Win32; там, где он недоступен, проверка деградирует до отчётности на основе состояния. | Проверено |

## Почему эти пределы существуют

| Причина | Примеры |
|---------|---------|
| Осознанная граница области | Создание-удаление PivotTable/PivotCache; диаграммы, сводные диаграммы, слайсеры; создание книги |
| Граница владения | Структурные операции диапазона над ListObject (`LISTOBJECT_INTERSECTION`) маршрутизируются к инструментам Tables |
| Ограничение платформы / сборки | Неактивирующая компиляция; `PivotFilters.Add` не поддерживается; `Workbook.PivotTables` не является пригодным инвентарём |
| Позиция безопасности | Нет инструмента approval-гранта; `macro_run` требует `background_safe`; нет автоматизации GUI |
| Не реализовано | Размеры строк/колонок, закрепление областей, параметры страницы; внешние ссылки; события; импорт/экспорт/печать/эл. почта |

## Ограничения VBA и COM

- **Требуется доверие VBOM.** Без «Trust access to the VBA project object model» каждый инструмент
  VBA/VBIDE и `vba_compile` возвращает `ACCESS_VBOM_DISABLED`.
- **Заблокированные проекты никогда не обходятся.** Проект, защищённый паролем, возвращает
  `VBA_PROJECT_LOCKED`; сервер никогда не пытается его разблокировать.
- **Нет добавления/удаления компонентов.** Компоненты нельзя создавать или удалять через MCP.
- **Нет дизайн-режима форм.** UserForms нельзя проектировать или редактировать; компоненты
  `UserForm` и Document-модули отклоняются инструментами замены исходников.
- **Нет изменения ссылок.** Ссылки можно перечислить (с пометкой сломанных), но не добавлять и не
  удалять.
- **Нет изменения защиты проекта.** Защита — только диагностика для чтения.
- **Единственный скрытый, неактивируемый экземпляр.** Сервер владеет одним экземпляром
  `DispatchEx("Excel.Application")`, удерживаемым в `Visible=False`. Он никогда не подключается к
  пользовательскому экземпляру, не активирует окно и не отправляет ввод.
- **Нет `.Activate` / `.Select` / `SendKeys`.** Автоматизации GUI нет.
- **`DisplayAlerts=False` не является универсальным блокиратором диалогов.** Он не блокирует
  `MsgBox`, `UserForm.Show`, `FileDialog`, UI надстроек или Win32-диалоги.

## Параллелизм и производительность

- **Один экземпляр Excel.** Весь доступ к COM сериализован на одном выделенном STA-потоке-воркере
  (`ExcelComWorker`); инструменты никогда не обращаются к COM напрямую.
- **Блокировка на путь.** `asyncio.Lock` удерживается на время жизни открытой книги, поэтому
  повторное открытие того же канонического пути сериализуется.
- **Мягкие таймауты.** Большинство операций используют 60-секундный таймаут по умолчанию
  (`_DEFAULT_TIMEOUT_S = 60.0`). Диспетчеризация `macro_run` использует 90 секунд по умолчанию
  (`macro_timeout_s`, настраивается через `EXCEL_VBA_MCP_MACRO_TIMEOUT_S`, F2b); тест-раннер
  использует `_CALL_TIMEOUT_S = 60.0` и `_MACRO_TIMEOUT_S = 120.0`. `orphan_timeout_s` воркера по
  умолчанию 10 секунд.
- **Нет слепого повтора мутаций.** Вызовы `READ_ONLY` могут повторяться не более 3 раз для
  `RPC_E_CALL_REJECTED` (паузы 0,5 / 1,0 / 2,0 секунды). Вызовы `MUTATING` и `EXECUTING` никогда не
  воспроизводятся повторно.
- **Ограниченные чтения.** Чтения диапазонов ограничены 100 000 ячеек на цель и 50 000 ячеек на
  ответ; чтения строк таблицы дополнительно ограничены 2 000 ячеек на ответ. Сверхбольшие запросы
  отклоняются, а не «молча» урезаются.
- **Пределы для больших книг.** Очень большие книги увеличивают использование памяти и задержку
  COM-вызовов; вызов, превысивший свой мягкий дедлайн, переводит воркер в `NEEDS_RECOVERY` и
  поднимает `EXCEL_HUNG`. Читайте большие диапазоны порциями через `offset` / `limit`.

## Внешние зависимости и известные проблемы

- **`mcp` разрешается в 2.3.x.** `pyproject.toml` объявляет `mcp>=2.3,<3`; lock разрешает 2.3.0. Код
  использует API `MCPServer` SDK v2.
- **Зависимости только для Windows.** `pywin32` и `comtypes` работают только на Windows, что является
  главной причиной того, почему сервер работает только на Windows.
- **Поведение, специфичное для сборки Excel.** `Workbook.PivotTables` не является пригодным инвентарём
  на целевой сборке, `PivotFilters.Add` не поддерживается, а неактивирующая компиляция недоступна.
  Это свойства валидированной сборки, а не ошибки конфигурации.
- **`macro_policy.classify_operation` неавторитетен.** Функция сохранена для иллюстрации, не
  подключена к энфорсменту, а её таблица устарела. Используйте код сервисов или
  [Справочник инструментов MCP](05-mcp-tools-reference.md).
- **`MODAL_UI_BLOCKED` объявлен, но не используется.** Он входит в стабильный словарь `ErrorCode`, но
  не выдаётся текущими адаптерами.
- **Нет общего in-band восстановления.** Сервер не предоставляет инструмент восстановления;
  единственный автоматический путь — зависание/таймаут `macro_run`, который пересоздаёт
  принадлежащий экземпляр в процессе (F2b). В остальных случаях решение — закрыть/открыть или
  перезапуск процесса.
- **Preflight R13 эвристичен.** См. [Безопасность](08-security.md) для остаточной границы
  ложно-безопасного.

## Проверено против предполагаемого

| Категория | Элементы |
|-----------|----------|
| Проверено (код или валидированная сборка) | Инвентарь инструментов; path policy; режимы approval; снапшот перед мутацией; компиляция `indeterminate`; гейтинг макросов; таймауты; ограниченные чтения; скрытый неактивируемый экземпляр; отсутствие автоматизации GUI |
| Предполагается / не проверено | Не-`.xlsm` форматы; сопоставление событий ActiveX; поведение компиляции на сборках, отличных от 16.0.14332; поведение при неанглийском UI Office; поведение, когда корпоративная политика блокирует VBOM или макросы |

Если поведение не указано здесь и не в коде, считайте его неподдерживаемым, а не предполагаемым. При
сомнениях проверяйте read-only-сессией на копии книги.

## Эксплуатационные заметки

Эти модели поведения следуют из модели сессий в [Архитектура](04-architecture.md):

- **Оригиналы никогда не изменяются.** `excel_open` копирует источник в `work/` и открывает только
  копию.
- **Правки живут в рабочей копии.** `excel_close` удаляет её; поздний `excel_open` повторно копирует
  нетронутый оригинал. Используйте `snapshot_create` → `excel_close` → `snapshot_restore`, чтобы
  сохранить и вернуться к прежнему состоянию.
- **Сохранения явные.** `excel_close` по умолчанию не сохраняет; `excel_save` или
  `excel_close(save_changes=true)` записывает только рабочую копию.
- **Снапшоты восстанавливают файлы, а не внешние эффекты.** Снапшот никогда не отменяет записи в
  базу данных, электронные письма, сетевые вызовы, файлы или печать.
- **Одна книга на путь.** Блокировка на путь сериализует открытия; повторное открытие того же
  канонического пути отклоняется, пока он открыт.

## Чек-лист совместимости перед развёртыванием

- [ ] Windows 10/11 x64 с настольным Excel (не UWP/Store-версия), активирован.
- [ ] Сборка Excel зафиксирована (валидировано: 16.0.14332); перепроверьте, если отличается.
- [ ] Python 3.11–3.14 x64 и `uv` в `PATH`.
- [ ] `EXCEL_VBA_MCP_ROOTS` указывает на выделенный каталог.
- [ ] Доверие VBOM включено, если требуются инструменты VBA.
- [ ] Read-only `excel_open` → `range_read_values` → `excel_close` smoke-тест проходит.
