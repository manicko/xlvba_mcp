## Назначение

Документ отвечает ровно на один вопрос: **что ИИ-агент реально может делать в Excel через
`xlvba`?**

Это карта возможностей, а не руководство по инструментам. Для каждой области объектной модели
Excel указано, какие операции существуют, какие MCP-инструменты их реализуют, как операция
выполняется внутри и чего сознательно нет. Исчерпывающий контракт по каждому инструменту
(параметры, DTO, ошибки) приведён в [Справочник инструментов MCP](05-mcp-tools-reference.md);
этот документ классифицирует поверхность и её пределы.

Два факта задают рамку для всего нижеизложенного:

1. `xlvba` управляет **единственным скрытым, неактивируемым экземпляром Excel** через COM на
   одном STA-потоке-воркере. Нет GUI, нет активации окон и нет ввода с клавиатуры.
2. Сервер по умолчанию работает в **режиме полного доступа**: мутирующие и исполняющие
   операции авторизованы без внутрипроцессного гранта. Установка
   `EXCEL_VBA_MCP_ACCESS_MODE=restricted` включает approval по принципу deny-by-default, при
   котором такие операции отклоняются с `APPROVAL_DENIED`.
   «Реализовано» и «разрешено через MCP» всё ещё различаются (перед мутацией нужен базовый
   снапшот, а `macro_run` требует классификации `background_safe`), поэтому каждая строка ниже
   сохраняет это разделение.

## Как читать этот документ

### Статусы покрытия

| Статус | Значение |
|--------|----------|
| **Полностью поддерживается** | У `xlvba` есть реализованный, ограниченный путь для операции, с валидацией и чтением postcondition там, где операция мутирует. Для мутирующих строк это означает «реализовано и защищено (guarded)», а не «свободно вызывается через MCP». |
| **Частично поддерживается** | Некоторые подоперации или варианты работают, а другие отклоняются или вне области, либо результат по своей природе ограничен (например, всегда-`indeterminate` компиляция или только ручные фильтры PivotTable). |
| **Не поддерживается** | Инструмента для этой возможности нет. Ничто в сервере её не предоставляет. |
| **Не проверено** | Путь разрешён или подразумевается, но поведение не валидировано на целевой сборке Excel (валидированная сборка: Excel 16.0.14332, `.xlsm`). |

Покрытие описывает **поверхность объектной модели Excel**. Это не означает, что операция
безусловно разрешена через MCP. В режиме `full` по умолчанию мутирующие и исполняющие операции
авторизованы (перед мутацией всё равно нужен снапшот); в режиме `restricted` они запрещены по
умолчанию. Колонка ограничений в каждой строке говорит об этом явно. Модель безопасности — в
[Архитектура](04-architecture.md).

### Виды операций

| Вид | Значение | Класс approval в MCP |
|-----|----------|----------------------|
| READ | Возвращает информацию, не меняя состояние книги. | `read-only`, разрешён автоматически. |
| CREATE | Добавляет новый объект, строку или правило. | `mutating`, guarded. |
| UPDATE | Изменяет существующий объект, значение или свойство. | `mutating`, guarded. |
| DELETE | Удаляет объект, строку или содержимое ячейки. | `mutating`, guarded. |
| EXECUTE | Запускает код (макрос или декларативный набор). | `executing`, guarded и дополнительно гейтится. |

### Цепочка защиты одной строкой

Каждый инструмент CREATE/UPDATE/DELETE/EXECUTE проходит один и тот же порядок: **writable-сессия →
снапшот → approval → проверки, специфичные для операции → перечитывание postcondition + аудит**.
Полная цепочка и её обоснование — в [Архитектура](04-architecture.md).

## Матрица возможностей

| Возможность Excel | Поддерживаемые операции | MCP-инструменты | Покрытие | Ограничения |
|-------------------|-------------------------|-----------------|----------|-------------|
| Управление приложением (скрытый экземпляр, здоровье, восстановление) | READ | `server_health`, `excel_health`, `excel_list_workbooks`, `excel_get_status` | Полностью поддерживается | `server_health` никогда не обращается к COM; `excel_health` возвращает `ok` / `needs_recovery` / `unavailable` без принудительного перезапуска. Не существует `.Activate`, `.Select`, `ShowWindow` или `SendKeys`. Восстановление неявное: поздний вызов пересоздаёт принадлежащий экземпляр. |
| Открытие книги (существующий файл, inspect/execute, только чтение) | READ / EXECUTE | `excel_open` | Полностью поддерживается | Оригинал копируется в `work/`, и открывается только копия. Открытие по умолчанию доступно для записи и выполнения (`mode="execute"`, `read_only=False`), авторизовано в режиме `full` и отклоняется с `APPROVAL_DENIED` в режиме `restricted`. Путь должен находиться внутри `EXCEL_VBA_MCP_ROOTS` (`PATH_NOT_ALLOWED`). |
| Закрытие и сохранение книги | UPDATE | `excel_close`, `excel_save` | Полностью поддерживается | `excel_close` без сохранения разрешён; `save_changes=true` и `excel_save` — мутирующие (авторизованы в режиме `full`; `APPROVAL_DENIED` в режиме `restricted`). Закрытие удаляет рабочую копию; правки живут только в рабочей копии, поэтому используйте восстановление из снапшота, чтобы сохранить и вернуться к прежнему состоянию. Изменения никогда не сохраняются неявно. |
| Создание книги (новая книга) | CREATE | — | Не поддерживается | Инструмента для новой книги нет. `excel_open` открывает только существующий файл; новую книгу через MCP создать нельзя. |
| Модель книги (агрегированное чтение) | READ | `workbook_get_model` | Полностью поддерживается | Агрегирует листы, таблицы, имена, фигуры, элементы управления, опциональный VBA и опциональные сводные таблицы со статусом по каждой секции. Никогда не читает все ячейки и не выполняет VBA. Когда VBOM недоступен, остальные секции всё равно возвращаются. |
| Листы: список и получение | READ | `sheets_list`, `sheet_get` | Полностью поддерживается | Перечисляет коллекцию `Sheets` (рабочие, диаграммные, макросные, диалоговые листы). Сообщает `code_name` только для чтения, `protected`, `table_count` и `used_range` для рабочих листов. |
| Листы: добавление, переименование, копирование, удаление, видимость | CREATE / UPDATE / DELETE | `sheet_add`, `sheet_rename`, `sheet_copy`, `sheet_delete`, `sheet_set_visibility` | Частично поддерживается | Все мутирующие (авторизованы в режиме `full`; `APPROVAL_DENIED` в режиме `restricted`). `sheet_add` поддерживает только `worksheet`. `sheet_copy` — копирование внутри книги, размещаемое после последнего листа; нет межкнижного копирования и произвольной позиции. `sheet_delete` отказывается оставлять ноль видимых листов; `sheet_set_visibility` отказывается скрывать последний видимый лист. Инструмента перемещения/переупорядочивания листов нет. |
| Ячейки и диапазоны: чтение значений | READ | `range_get`, `range_read_values` | Полностью поддерживается | Ограниченные окна (`offset` с 0, `limit`); жёсткие пределы: 100 000 ячеек на цель и 50 000 ячеек на ответ. Сверхлимитные запросы отклоняются, а не «молча» урезаются; `truncated=true` отмечает урезанное окно. `range_get` сообщает геометрию объединённых ячеек (`is_merged`, `merged_area`): цель считается единым объединённым блоком только когда все её ячейки принадлежат одной `MergeArea`, внутренние ячейки/поддиапазоны разрешаются в anchor-область, а после `range_unmerge` `is_merged` снова `false` (F1). |
| Ячейки и диапазоны: запись значений | CREATE / UPDATE | `range_write_values` | Полностью поддерживается | Guarded-мутация. Форма payload должна точно совпадать с целью. Строка, начинающаяся с `=`, сохраняется как **текст**, а не как формула. Запись ячеек внутри таблицы разрешена только при неизменной структуре строк/колонок таблицы. |
| Ячейки и диапазоны: чтение формул | READ | `range_read_formulas` | Полностью поддерживается | `Formula2` как основной, `Formula` как запасной. Префиксы `_xlfn` / `_xlws` / `_xlpm` возвращаются дословно и отмечаются в `notes`. |
| Ячейки и диапазоны: запись формул | UPDATE | `range_write_formulas` | Полностью поддерживается | Guarded-мутация. Каждая запись должна быть строкой формулы, начинающейся с `=`; константы относятся к `range_write_values`. То же правило структуры ListObject, что и для записи значений. |
| Ячейки и диапазоны: копирование, вставка, удаление | CREATE / UPDATE / DELETE | `range_copy`, `range_insert`, `range_delete` | Частично поддерживается | Только в пределах одной книги, без буфера обмена. `range_insert`/`range_delete` требуют явного `shift` (`right`/`down`, `left`/`up`); никогда не угадывается. Защищённые листы, пересечения с ListObject (`LISTOBJECT_INTERSECTION`), диапазоны динамических массивов (spill) и объединённые ячейки (если не указан `allow_merged`) отклоняются. `range_copy` требует совместимую по форме цель и отклоняет объединённые получатели. |
| Ячейки и диапазоны: объединение и разъединение | UPDATE | `range_merge`, `range_unmerge` | Частично поддерживается | Объединение предварительно просматривает неякорные ячейки с данными и блокирует с `INVALID_RANGE`, если не передан `allow_data_loss=true`; `across=true` объединяет по одной ячейке в строке. Разъединение срабатывает только когда объединённая область действительно пересекает цель. Оба отклоняют ListObject и spill-цели. |
| Форматирование и стили | READ / UPDATE | `range_get_format`, `range_set_format` | Частично поддерживается | Чтение три-state: значение, `mixed` (ячейки расходятся) или `unsupported`; смешанный диапазон никогда не «уплощается». Разреженный (sparse) patch открывает 11 полей: `number_format`, `font_name`, `font_bold`, `font_italic`, `font_size`, `font_color`, `fill_color`, `fill_pattern`, `alignment_horizontal`, `alignment_vertical`, `alignment_wrap_text`. Нет границ, размеров строк/колонок и копирования имён стилей. |
| Проверка данных (data validation) | READ / UPDATE | `range_get_validation`, `range_set_validation` | Частично поддерживается | Типы: список, целое число, десятичное, дата, время, длина текста, custom (`input_only` сообщается, но никогда не задаётся). `Formula1`/`Formula2` — непрозрачные строки с пределом 255 символов, которые никогда не вычисляются. Неоднородная цель сообщается (`non_uniform_validation`), а не «уплощается». |
| Условное форматирование | READ / CREATE / UPDATE / DELETE | `range_get_conditional_formatting`, `range_set_conditional_formatting` | Частично поддерживается | Только простые типы `FormatCondition`: значение ячейки, выражение, текстовая строка, пустые, непустые, ошибки, без ошибок, период времени, топ-10, выше среднего, уникальные значения. `ColorScale`, `DataBar` и `IconSet` сообщаются с `supported=false` и отклоняются при записи. `priority` — единственная стабильная идентичность; приоритеты действуют на весь лист и перенумеровываются. |
| Именованные диапазоны: список и получение | READ | `names_list`, `name_get` | Полностью поддерживается | Области книги и листа; `RefersTo` / `RefersToLocal`, `Visible` и классификация `target_kind`. Имена, не являющиеся диапазонами, классифицируются эвристически по строке; нет `Application.Evaluate` и нет Python `eval`. |
| Именованные диапазоны: создание, обновление, удаление | CREATE / UPDATE / DELETE | `name_create`, `name_update`, `name_delete` | Полностью поддерживается | Guarded-мутация. Область задаётся явно (`workbook` или `worksheet` + владелец-лист); дубликаты и конфликты областей отклоняются. `name_update` сохраняет область. |
| Таблицы Excel: список, получение, чтение строк | READ | `tables_list`, `table_get`, `table_read_rows` | Полностью поддерживается | Полные ограниченные списки, без пагинации. `table_read_rows` использует `offset` с 0 и `limit`; ответ дополнительно ограничен 2 000 ячеек с флагом `truncated`. |
| Таблицы Excel: добавление, вставка, обновление, удаление строк | CREATE / UPDATE / DELETE | `table_append_rows`, `table_insert_row`, `table_update_rows`, `table_delete_rows` | Полностью поддерживается | Guarded-мутации. Добавление/вставка идут через `ListRows.Add`, поэтому структура таблицы сохраняется. `table_insert_row` использует 1-based `at`. Обновление/удаление принимают явные индексы или **однозначный** `where`; неоднозначность отклоняется с предпросмотром, а не угадывается. |
| Таблицы Excel: добавление и удаление колонок | CREATE / DELETE | `table_add_column`, `table_delete_column` | Полностью поддерживается | Guarded. Добавление использует `ListColumns.Add(Position)` с уникальным заголовком; удаление разрешает один уникальный заголовок. |
| Таблицы Excel: создание и изменение размера | CREATE / UPDATE | `table_create`, `table_resize` | Полностью поддерживается | Guarded. Создание использует `ListObjects.Add` над A1-диапазоном или определённым именем; изменение размера — `ListObject.Resize`. |
| PivotTables: список, получение, кэш, поля | READ | `pivot_tables_list`, `pivot_table_get`, `pivot_cache_get`, `pivot_fields_list` | Полностью поддерживается | Перечисление — это обход по листам, поскольку `Workbook.PivotTables` непригоден на целевой сборке. Кэши идентифицируются 1-based `CacheIndex`; общие кэши сообщаются один раз с затронутыми таблицами. Ячейки вывода никогда не материализуются. |
| PivotTables: обновление | UPDATE | `pivot_table_refresh`, `pivot_cache_refresh` | Частично поддерживается | Обновление таблицы использует `PivotTable.RefreshTable`; обновление кэша — `PivotCache.Refresh`. Обновляются только кэши на базе базы данных/таблицы; внешние, OLAP и Data Model источники возвращают `UNSUPPORTED_PIVOT_SOURCE`. `Workbook.RefreshAll` никогда не используется. |
| PivotTables: макет, позиция, агрегация, свойства | UPDATE | `pivot_field_set_layout`, `pivot_field_set_position`, `pivot_field_set_aggregation`, `pivot_field_set_properties` | Частично поддерживается | Макет принимает hidden/row/column/page; `orientation="data"` отклоняется, а агрегация должна задаваться через `pivot_field_set_aggregation`. Принимаются только одиннадцать кодов агрегации; устаревшие коды отклоняются. `pivot_field_set_properties` разреженный (`caption`, `number_format`, `show_all_items`) и требует уникального заголовка. |
| PivotTables: фильтры | READ / UPDATE | `pivot_field_get_filters`, `pivot_field_apply_filter`, `pivot_field_clear_filters` | Частично поддерживается | Только ручные фильтры по видимым элементам (`PivotItems[i].Visible`). Фильтры по метке, значению, дате и верхним/нижним (`PivotFilters.Add`) не поддерживаются на целевой сборке и возвращают явный unsupported-результат, а не конвертируются. Область очистки — `field` или `table`. Поля страницы (report-filter) классифицируются по `CurrentPage` / `AllItemsVisible` (F3): нетронутое поле страницы сообщает `kind:"none"`, `hidden_items:[]`, что совпадает с `pivot_table_get.filter_state`; очистка нетронутого поля страницы больше не поднимает ложный `AMBIGUOUS_FILTER`; `pivot_field_apply_filter` для поля страницы отклоняется (`supported:false`), а не «понижается». |
| PivotTables и PivotCaches: создание или удаление | CREATE / DELETE | — | Не поддерживается | Ни один инструмент не создаёт и не удаляет PivotTable или PivotCache. Существующие объекты можно только инспектировать, обновлять и перенастраивать. |
| Фигуры: список, получение, назначение on-action | READ / UPDATE | `shapes_list`, `shape_get`, `shape_set_on_action` | Частично поддерживается | Только инвентаризация и назначение `OnAction`. Нет создания, удаления, форматирования, группировки, порядка по z или редактирования текста фигур. `on_action` читается дословно и никогда не выполняется; пустой `macro_name` снимает назначение. |
| Элементы управления (Form Controls и ActiveX): список, получение, назначение on-action | READ / UPDATE | `controls_list`, `control_get`, `control_set_on_action` | Частично поддерживается | Form Controls сообщают тип, заголовок (caption), связанную ячейку и `on_action`; ActiveX сообщает `prog_id` и **предполагаемую** (inferred) процедуру события. `control_set_on_action` записывает `OnAction` только для Form Controls; элементы ActiveX отклоняются, поскольку у них нет семантики `OnAction`. Нет создания, удаления или редактирования свойств элементов. |
| Проект VBA: информация, компоненты, процедуры, чтение, экспорт, ссылки, поиск | READ | `vba_project_info`, `vba_list_components`, `vba_list_procedures`, `vba_read_component`, `vba_export_project`, `vba_get_references`, `vba_search_code` | Полностью поддерживается | Требует доверия VBOM (иначе `ACCESS_VBOM_DISABLED`) и незаблокированного проекта (`VBA_PROJECT_LOCKED`). Процедуры читаются через API VBIDE CodeModule с эвристическими запасными путями, отмеченными флагом. Экспорт записывает `.bas` / `.cls` / `.frm` + `.frx` под артефакт-корнями и возвращает хэши по файлам; Document-модули никогда не удаляются. |
| Редактирование VBA: замена исходника, вставка кода | UPDATE | `vba_replace_component_source`, `vba_insert_code` | Частично поддерживается | Только модули Standard и Class (Document-модули и UserForms отклоняются). Требует совпадающего токена ревизии `expected_source_hash` — это **нормализованный `source_hash`** из `vba_read_component`, а не хэш файла экспорта снапшота (`snapshot_create.vba_exports[].export_file_sha256`) (F7) — который проверяется до и внутри STA-воркера; несовпадение поднимает `REVISION_CONFLICT` с `reason="revision_conflict"` (таксономия F-5; `COM_BUSY` зарезервирован для реальной конкуренции). Guarded-мутация (авторизована в режиме `full`; `APPROVAL_DENIED` в режиме `restricted`). |
| Диагностика компиляции | READ | `vba_compile`, `vba_get_compile_diagnostics` | Частично поддерживается | Fail-closed по замыслу: на валидированной сборке статус всегда `indeterminate` с `reason="NON_ACTIVATING_COMPILE_UNAVAILABLE"` и `diagnostics.is_compile=false`. Никогда не возвращает `compiled` или `compile_error` и не показывает UI. Причины: `NON_ACTIVATING_COMPILE_UNAVAILABLE`, `ACCESS_VBOM_DISABLED`, `VBA_PROJECT_LOCKED`. |
| Выполнение макросов | EXECUTE | `macro_list`, `macro_run`, `macro_get_last_result`, `macro_classify_background` | Частично поддерживается | Гейты: execute-режим + writable-сессия → разрешение процедуры → approval (авто в режиме `full`) → `background_safe` для текущего хэша книги **и** ревизии исходников VBA → preflight интерактивного UI (R13). `BackgroundSafetyRegistry` стартует пустым (fail-closed), но наполняется через `macro_classify_background`; неклассифицированная процедура возвращает `BACKGROUND_SAFETY_NOT_VERIFIED`, интерактивная — `INTERACTIVE_UI_NOT_SUPPORTED`. У диспетчеризации мягкий дедлайн 90 с (`EXCEL_VBA_MCP_MACRO_TIMEOUT_S`), и она выполняется с `Application.Interactive=False` / `DisplayAlerts=False`, восстанавливаемыми в `finally` (F2a, только defense-in-depth). По таймауту owned PID проверяется только для чтения на модальное окно (`MACRO_RUNTIME_ERROR`, `dismissed=false`) или без него (`MACRO_TIMEOUT`); в обоих случаях завершается только owned PID, а сессия восстанавливается в процессе — это сообщается как `MacroRunResult.session_recovery` (`recovered` / `needs_recovery`), открытые книги отбрасываются (F2b). Токен-скан R13 — эвристический запрет, а не статическое доказательство (динамическая косвенность `CallByName`/`ExecuteGlobal`/`Eval` и транзитивный UI покрыты не полностью; список запретов всё же включает `AppActivate`, `Application.Visible`, `.Activate`, `WindowState`). Слепого повтора нет. |
| Снапшоты | READ / CREATE / UPDATE | `snapshot_create`, `snapshot_list`, `snapshot_diff`, `snapshot_restore` | Полностью поддерживается | Открытые книги используют `Workbook.SaveCopyAs`, закрытые — копирование файла. Снапшоты иммутабельны, несут манифест (`model_version: 2`) и SHA-256. Каждая запись `vba_exports` содержит `export_file_sha256` (хэш байтов экспортированного **файла**, отличный от нормализованного `source_hash`) (F7). `snapshot_restore` — guarded-мутация и **не** отменяет внешние эффекты макросов. `snapshot_diff` сравнивает метаданные манифеста и верхнеуровневые хэши файлов снапшотов, но никогда не бинарный diff. |
| Декларативный тестовый раннер | EXECUTE | `test_run_suite`, `test_suite_run`, `test_get_run` | Частично поддерживается | Закрытые словари: 37 ограниченных действий и 29 проверок только для чтения, `extra="forbid"`; неизвестные действия или неограниченные payload отклоняются до любого обращения к Excel. Один иммутабельный baseline и одна одноразовая копия на кейс. Последовательность edit→macro→edit→macro поддерживается через необязательное поле шага `background_safe` только с данными (раннер классифицирует через защищённый путь перед запуском); компиляция перед макросом явная (шаг `vba_compile`). Шаги `vba_replace_component_source` и `vba_insert_code` отклоняются раннером, поскольку декларативный шаг не может нести хэш ревизии. В режиме `restricted` прогон — `blocked` (`APPROVAL_DENIED`); шаг макроса по неклассифицированной процедуре — `blocked` (`BACKGROUND_SAFETY_NOT_VERIFIED`). |
| Диаграммы, сводные диаграммы и слайсеры | — | — | Не поддерживается | Ни один инструмент не перечисляет, не создаёт, не форматирует и не удаляет диаграммы, сводные диаграммы или слайсеры. Диаграммный лист виден только как запись `chart` в `sheets_list`. |
| Размеры строк/колонок и макет листа (ширина, высота, закрепление областей, параметры страницы) | — | — | Не поддерживается | Ни один инструмент не предоставляет высоту строки, ширину колонки, закрепление областей, настройки печати/страницы или масштаб. `range_get_format` охватывает только ячейки. |
| Защита листа | — | — | Не поддерживается | `sheets_list` / `sheet_get` сообщают флаг `protected` только для чтения. Инструмента защиты/снятия защиты нет, а мутирующие инструменты отклоняют защищённую цель с `PROTECTED_TARGET`. |
| Вычисление книги | — | — | Не поддерживается | Инструмента для `Application.Calculate` или свойств вычисления нет. `range_read_values` возвращает кэшированные/вычисленные значения, которые Excel удерживает в данный момент; ничто не форсирует пересчёт. |
| Внешние ссылки, подключения и запросы | — | — | Не поддерживается | Ни один инструмент не перечисляет, не обновляет и не редактирует внешние ссылки, подключения к данным или определения Power Query. |
| Импорт, экспорт, печать, PDF и электронная почта | — | — | Не поддерживается | Нет импорта/экспорта CSV, экспорта в PDF, печати, электронной почты или конвертации файлов. `vba_export_project` экспортирует только исходники VBA. |
| События и обработчики событий | — | — | Не поддерживается | Ни один инструмент не регистрирует, не перечисляет и не редактирует события книги/листа. Процедуры событий ActiveX только предполагаются для чтения. |
| Не-`.xlsm` форматы Excel | READ / CREATE / UPDATE | `excel_open` и все инструменты книги | Не проверено | Allowlist путей принимает `.xlsm .xlsb .xlsa .xlam .xltm .xltx .xlsx .xls`, но на целевой сборке валидирован только `.xlsm`. Поведение с другими расширениями не проверено. |

## Поддержка формул (отдельно от объектной модели Excel)

Формулы Excel, такие как `SUM`, `VLOOKUP`, `XLOOKUP` или `FILTER`, **не** являются
возможностью `xlvba` в смысле объектной модели. Это содержимое листа, которое `xlvba` может
читать и записывать как строки, но `xlvba` не является движком вычислений.

Три различные операции нельзя путать:

| Операция | Инструмент | С чем работает | Что возвращает |
|----------|------------|----------------|----------------|
| Чтение текста формулы | `range_read_formulas` | `Range.Formula2` (основной) и `Range.Formula` (запасной) | Ограниченная сетка значений `FormulaCell`. `formula2` присутствует всегда; `formula` включается только при отличии (например, добавленный Excel неявный `@` пересечения). Префиксы `_xlfn`, `_xlws` и `_xlpm` сохраняются дословно и отмечаются в `notes`. |
| Запись текста формулы | `range_write_formulas` | `Range.Formula2` (запасной `Range.Formula`) | `RangeMutationResult` с перечитанной сеткой формул и флагом `verified`. Каждая запись должна начинаться с `=`; голая константа отклоняется. |
| Чтение вычисленных значений | `range_read_values` | `Range.Value2` | Типизированные ячейки: `string`, `number`, `boolean`, `date`, `error`, `empty`. Даты типизируются только по числовому формату ячейки. |

Явные границы:

1. `xlvba` **не** предоставляет движок вычислений. Он никогда не вычисляет формулу в Python
   и никогда не вызывает `Application.Evaluate`.
2. `xlvba` **не** предоставляет `Application.Calculate` (или `CalculateFull`, `CalculateRow` или
   какое-либо свойство вычисления). Нет инструмента, чтобы форсировать пересчёт.
3. `xlvba` **не** гарантирует пересчитанные значения после записи. `range_write_formulas`
   записывает строки формул; значения, возвращаемые поздним `range_read_values`, — это то, что
   Excel удерживает в рабочей копии в данный момент. Если Excel не пересчитал, кэшированное
   значение может быть устаревшим или пустым.
4. Формулы динамических массивов читаются в их форме `Formula2`. Диапазон spill — защищённая
   цель для структурных операций: `range_insert`, `range_delete` и `range_merge` его отклоняют.

Разобранные примеры — в [Рабочие процессы и примеры](07-workflows-and-examples.md), рабочие
процессы 2 и 7.

## Подробности по областям

### Жизненный цикл сессии и книги

Агент сначала вызывает `excel_open` с путём внутри `EXCEL_VBA_MCP_ROOTS`. Открытие по умолчанию —
`mode="execute", read_only=False` (writable, с возможностью выполнения). Сервер копирует файл в
`work/`, хэширует его, открывает **копию** в скрытом экземпляре и возвращает `workbook_id`.
`mode="inspect"` отключает макросы для открытия (`AutomationSecurity = ForceDisable`); `mode="execute"`
применяет `ByUI` непосредственно перед `Open`. Ни один из режимов не меняет настройки Trust Center
или реестра. `excel_close` закрывает рабочую копию и удаляет её; `excel_save` явно её записывает.
Оригинал никогда не изменяется никаким инструментом. Правки живут только в рабочей копии, поэтому
буквальное «закрыть, затем открыть снова» не показывает прежних правок; сохраняйте и откатывайтесь
через `snapshot_create` → `excel_close` → `snapshot_restore`.

Не предоставляется: свойства книги, пользовательские свойства документа, защита на уровне книги,
варианты `Workbook.Close`, управление надстройками или операция создания новой книги.

### Листы

Реализовано над коллекциями `Sheets` / `Worksheets` Excel. Инструменты чтения возвращают
`SheetInfo` (имя, индекс, тип объекта, видимость, `code_name`, защита, количество таблиц,
используемый диапазон). Мутирующие инструменты вызывают `Sheets.Add`, `Worksheet.Name`,
`Worksheet.Copy`, `Worksheet.Delete` и `Worksheet.Visible`. `sheet_copy` привязывает копию через
`Before`/`After`, чтобы гарантировать копирование внутри книги, а не в новую книгу. Не
предоставляется: перемещение/переупорядочивание листов, защита на уровне листа, параметры печати,
цвет вкладки и создание диаграммных листов.

### Ячейки и диапазоны

Реализовано над `Worksheet.Range`, `Range.Value2` и `Range.Formula2`. Чтения — ограниченные окна
над явным A1-адресом. Записи — массовые 2-D payload, форма которых должна совпадать с целью.
Структурные операции используют `Range.Copy`, `Range.Insert`, `Range.Delete`, `Range.Merge` и
`Range.UnMerge` с явным shift. Защиты: защищённый лист (`PROTECTED_TARGET`), пересечение с
ListObject (`LISTOBJECT_INTERSECTION`), диапазон spill динамического массива, объединённые ячейки
без `allow_merged` и потеря данных при объединении без `allow_data_loss`. Postconditions перечитывают
цель и устанавливают `verified` из фактического состояния. Не предоставляется: копирование/вставка
через буфер обмена, межкнижное копирование, операции на EntireRow/EntireColumn, поиск/замена,
автозаполнение или случайные/волатильные функции.

### Форматирование и стили

Реализовано над `Range.Interior`, `Range.Font`, `Range.NumberFormat` и `Range.Alignment`.
`range_get_format` возвращает каждое свойство как значение, `mixed` или `unsupported` и перечисляет
имена смешанных свойств; он никогда не «уплощает» смешанный диапазон. `range_set_format` записывает
только поля, явно присутствующие в patch. Значения цветов — целые RGB/BGR, размер шрифта ограничен,
а строки формата ограничены 255 символами. Не предоставляется: границы, размеры строк/колонок,
стили ячеек, цвета темы, локализация числовых форматов или условные форматы (у них свои инструменты).

### Проверка данных (data validation)

Реализовано над `Range.Validation`. `range_set_validation` поддерживает типы с правилами и
изменяет существующее правило так, что неуказанные свойства сохраняются. `Formula1`/`Formula2` —
непрозрачные строки с пределом 255 символов, которые никогда не вычисляются. Цель, ячейки которой
не разделяют одно правило, сообщается как неоднородная, а не «уплощается». Не предоставляется:
проверка на таблицы в целом, редактирование только входного сообщения как отдельная операция или
межлистовые источники списков помимо непрозрачной строки формулы.

### Условное форматирование

Реализовано над `Range.FormatConditions`. Чтения возвращают правила в порядке возрастания
приоритета с ограниченным подмножеством заливки/шрифта. Записи добавляют, изменяют или удаляют одно
правило, идентифицируемое по `priority`; приоритеты действуют на весь лист, и остальные правила
перенумеровываются. `ColorScale`, `DataBar` и `IconSet` — отдельные COM-объекты вне ограниченной
области и отклоняются при записи. Не предоставляется: управление правилами через UI менеджера
условного форматирования, наборы значков, полосы данных, цветовые шкалы или цепочки stop-if-true
свыше одного патча правила.

### Именованные диапазоны

Реализовано над `Workbook.Names` и `Worksheet.Names`. Область задаётся явно; `RefersTo` хранится и
возвращается как непрозрачная строка; `target_kind` классифицируется эвристически на range, formula,
constant, external, error или unknown. Не предоставляется: вычисление имён, локальные для имени
константы с приведением типов или упорядочивание имён.

### Таблицы Excel (ListObject)

Реализовано над `ListObjects`, `ListRows` и `ListColumns`. Чтения возвращают диапазон, заголовок,
диапазоны тела данных и строки итогов, стиль, количество строк и колонки. Мутации строк используют
`ListRows.Add` и `ListRows.Item(i).Delete`; мутации колонок используют `ListColumns.Add(Position)`.
Создание использует `ListObjects.Add` над A1-диапазоном или определённым именем; изменение размера —
`ListObject.Resize`. Не предоставляется: стили/форматирование таблиц, функции строки итогов,
формулы структурированных ссылок, подключения слайсеров или объединение таблиц.

### PivotTables

Реализовано над `Worksheet.PivotTables`, `PivotCache`, `PivotFields`, `PivotItems` и
`PivotTable.RefreshTable`. Инвентаризация — обход по листам. Обновление — на уровне таблицы или
кэша и только для источников базы данных/таблицы. Макет, позиция, агрегация и свойства полей
патчатся и перечитываются. Фильтры — только ручные по видимым элементам. Не предоставляется:
создание или удаление PivotTables/PivotCaches, изменение исходного диапазона PivotTable,
вычисляемые поля/элементы, группировка, слайсеры, временные шкалы, `Workbook.RefreshAll` или
фильтры по метке/значению/дате/верхним-нижним.

### Фигуры и элементы управления

Реализовано над `Worksheet.Shapes` и `Worksheet.Shapes OLEObjects` / Form Controls. Инструменты
чтения сообщают тип, `on_action` дословно, видимость, позицию/размер и текст по мере возможности.
Единственная мутация — назначение `OnAction` (Form Controls и фигуры); элементы ActiveX отклоняются
для `OnAction` и только сообщают предполагаемую процедуру события. Не предоставляется: создание,
удаление, группировка, форматирование или переименование фигур и элементов.

### Проект VBA и исходники

Реализовано над объектной моделью VBIDE (`VBProject`, `VBComponents`, `CodeModule`) на STA-воркере.
Инструменты чтения требуют доверия VBOM и незаблокированного проекта. Процедуры перечисляются через
API CodeModule, с эвристическими запасными путями, отмеченными `is_heuristic`. Экспорт записывает
каждый компонент в `.bas` / `.cls` / `.frm` (+ `.frx`) и возвращает манифест с хэшами по файлам.
Две мутации заменяют модуль целиком или вставляют в семантическую позицию; обе требуют совпадающего
`expected_source_hash` и обе ограничены модулями Standard/Class. Не предоставляется: добавление или
удаление компонентов, правки в дизайн-режиме форм, изменение ссылок или изменение защиты проекта.

### Диагностика компиляции

Реализовано без запуска UI. `vba_compile` собирает доказательства только для чтения (доступность
VBOM, защита, состояние блокировки, инвентарь компонентов, сломанные ссылки, read-only проба
обнаружения команд VBE) и возвращает `status="indeterminate"` с `diagnostics.is_compile=false`. На
валидированной сборке причина всегда `NON_ACTIVATING_COMPILE_UNAVAILABLE`. `vba_get_compile_diagnostics`
возвращает кэшированный результат без повторного сбора. Не предоставляется: реальная компиляция, лог
сборки или список ошибок помимо сломанных ссылок.

### Макросы

Реализовано на STA-воркере через единственную диспетчеризацию `Application.Run`. Порядок гейтов:
execute-режим + writable-сессия, разрешение процедуры из `Module.Procedure`, гейт approval (авто в
режиме `full`), классификация `background_safe`, привязанная к хэшу книги и ревизии исходников VBA,
и preflight интерактивного UI. `macro_classify_background` записывает классификацию (ungated,
привязанную к хэшу исходников). Заблокированные макросы никогда не запускаются. Таймаут проверяет
принадлежащий PID только для чтения на наличие модального окна: если оно есть, прогон — это
`MACRO_RUNTIME_ERROR`, и завершается только принадлежащий PID (`dismissed=false`); иначе —
`MACRO_TIMEOUT` / needs-recovery. Токен-скан R13 — эвристический запрет, а не статическое
доказательство (динамическая косвенность `CallByName`/`ExecuteGlobal`/`Eval` и транзитивный UI
покрыты не полностью; список запретов всё же включает `AppActivate`, `Application.Visible`,
`.Activate`, `WindowState`). Не предоставляется: запуск макросов в inspect- или read-only-сессиях или
закрытие диалогов.

### Снапшоты

Реализовано через `storage/snapshot_store.py`. Открытые книги фиксируются через
`Workbook.SaveCopyAs`; закрытые книги копируются. Хранилище иммутабельно (скрытая промежуточная
область плюс атомарная замена), и каждый снапшот несёт манифест с SHA-256. Восстановление закрывает
текущую рабочую копию без сохранения и повторно открывает из baseline. Diff сравнивает только
метаданные манифеста и хэши файлов. Не предоставляется: бинарные diff'ы, частичное восстановление
или откат внешних эффектов макросов.

### Декларативный тестовый раннер

Реализован в `application/test_runner.py` поверх закрытой схемы в `domain/test_spec.py`. Каждый
кейс стартует с собственной одноразовой рабочей копии одного иммутабельного baseline-снапшота.
Действия и проверки берутся из закрытых enum'ов, поэтому неизвестное действие, payload с произвольным
кодом или неограниченная матрица отклоняются до любого обращения к Excel. Неудачный шаг `vba_compile`
блокирует последующие шаги `macro_run` в том же кейсе; `indeterminate`-компиляция не считается
провалом. Прогоны сохраняются под `runs/` и читаются через `test_get_run`. Не предоставляется:
произвольный Python, shell или COM в шаге либо декларативная замена защищённым инструментам
`vba_replace_component_source` / `vba_insert_code` (эти шаги отклоняются по замыслу).

## Не поддерживается и почему

| Отсутствующая возможность | Причина |
|---------------------------|---------|
| Создание или удаление PivotTables / PivotCaches | Вне области по замыслу. Контракт Phase 2 управляет только **существующими** PivotTables и кэшами; внешние/OLAP/Data-Model источники отклоняются. |
| Диаграммы, сводные диаграммы, слайсеры | Не реализовано. Адаптера или инструмента нет; диаграммный лист — только запись `chart` в `sheets_list`. |
| `PivotFilters.Add` (фильтры по метке/значению/дате/верхним-нижним) | Не поддерживается на валидированной сборке. `pivot_field_apply_filter` возвращает явный unsupported-результат с `filter.supported=false` и причиной; он никогда «молча» не конвертируется в ручной фильтр. |
| Создание новой книги | Инструмента нет. `excel_open` открывает только существующий файл, поэтому пустую книгу через MCP создать нельзя. |
| Структурные операции диапазона над ListObject | Отклоняются с `LISTOBJECT_INTERSECTION` и маршрутизируются к инструментам Tables. Это осознанная граница владения, а не отсутствующая возможность. |
| Изменение защиты листа или книги | Инструмента нет. Защита — только диагностика для чтения; защищённая цель отклоняется с `PROTECTED_TARGET`. |
| Форсированный пересчёт | `Application.Calculate` не предоставляется. Записи формул не гарантируют пересчитанного кэшированного значения. |
| Буфер обмена и межкнижное копирование | `range_copy` работает в пределах одной книги и никогда не использует буфер обмена. |
| Размеры строк/колонок, закрепление областей, параметры страницы | Инструмента нет. |
| Внешние ссылки, подключения, запросы, импорт/экспорт, печать, PDF, электронная почта | Инструмента нет. |
| События | Инструмента нет. |
| Выдача approval-гранта / управление allowlist | Гранты approval и записи allowlist сознательно не предоставляются через MCP. В режиме `full` по умолчанию грант не нужен (мутации/execute авторизованы); режим `restricted` повторно включает deny-by-default. Внутрипроцессный встраиватель (embedder) настраивает политику в коде. Классификация `background_safe` **предоставляется** через `macro_classify_background`. |
| Автоматизация GUI, диалоги, нажатия клавиш | Запрещено по замыслу. Экземпляр скрыт и неактивируем; `DisplayAlerts=False` не рассматривается как универсальный блокиратор диалогов. |
| Управление уровнем логирования на стороне сервера | `EXCEL_VBA_MCP_LOG_LEVEL` разбирается, но не применяется; логирование фиксировано на `INFO` в `stderr`. |

Покрытие для чтения широкое: каждая поверхность инвентаризации и чтения выше доступна через MCP без
